The mental model

Browser DevTools, mapped onto agents.

You already know how to debug a web page. Meterbility gives your agents the same five panels — all shipping today.

Elements→Context Viewer

See what the model saw

The fully resolved context for any step — system prompt, history, tool schemas — at /contexts/:id.

Sources→Step Inspector

Step through, fork from here

meter inspect walks every decision; meter fork branches a new trajectory from any step.

Network→I/O Inspector

Every request and result

Decision blobs, tool results, and files changed — including Bash side-effects other tools can't see.

Performance→Cost Timeline

Cost, tokens, latency

Per-step and per-run timelines. Know exactly where the money and the time went.

Console→Live Probe

Pause. Inject. Resume.

An operator surface for running agents — meter probe or the web panel. Intervene mid-run.

git→Trajectory Diff

Diff the timelines

meter diff compares two runs step-by-step and pinpoints exactly where behavior diverged.

What ships today

Full-fidelity capture. Local-first storage.

Everything runs on your machine: SQLite plus content-addressed blobs. Add Postgres when you need multi-machine sync.

🎥

Capture every surface

Claude Code JSONL hooks, Codex CLI & Desktop, Cursor composer, and Anthropic/OpenAI proxies via meter proxy.

🕵️

Bash side-effect capture

What tool-call inspection can't see — sed, mv, build scripts — lands as file-change rows via hooks or the FileSentinel.

🔀

Fork & replay

Deterministic prefix replay with a live suffix. Continue with --continue simulate|live for multi-step what-ifs.

🧪

Regression suite

Promote a good run to a canonical, add assertions, and catch behavioral drift with meter test.

📦

SDKs for custom agents

@meterbility/agent for TypeScript and meterbility-agent for Python (stdlib-only). One-line Anthropic tracing.

🔒

Sensitive-path redaction

Edits to .env, keys, and credential stores record the fact of the change — path, op, size — never the contents.
