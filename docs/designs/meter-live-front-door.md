# Design: `meter live` — one-command front door for ingest + side-effect capture, with step-range file views

Generated by /office-hours on 2026-08-19

## Problem Statement

The founder asked for (1) one command that starts session ingest and file side-effect capture together, (2) a view of file changes at a single step, (3) a view of changes from step X to the current step. Code reading showed most of this shipped: `meter watch --files` (packages/cli/src/commands/watch.ts) already runs LiveInspector + FileSentinel in one process; `meter files <run> --at <step>` (packages/cli/src/commands/files.ts) covers per-step; `meter files --diff <path> --from/--to` covers ranges but only per-path.

The real problem, in the founder's own words: "I'm just forgetting to start a session or ingest one with watch at start / the flow is confusing currently." Three overlapping mechanisms (hook capture, sentinel, ingest) with no single front door, plus one genuinely missing query shape: an all-files range summary ("everything changed from step X to now"), including against a live run.

## Demand Evidence

- Founder is a daily user of their own product and repeatedly fails to engage the capture flow — behavior, not opinion. Verbatim: "mainly I'm just forgetting to start a session or ingest one with watch at start."
- Fidelity distrust stated first ("I use it, fidelity disappoints"), then narrowed under pushing to one symptom ("It shows only additions") most plausibly explained by this host's documented fseventsd starvation coalescing create+edit histories into single all-additions rows (sentinel diff logic verified sound by code read; investigation filed separately).
- Positioning evidence (settled 2026-08-04): file side-effect provenance is a named differentiator for the audit/control category; sell-track has 3 booked calls that will demo exactly this surface.
- Gap named honestly: no non-maintainer has ever run the capture flow cold ("Only me so far"). Sample size of one; the assignment addresses it.

## Status Quo

Founder runs `meter watch --files` sometimes, forgets often, distrusts output when degraded, falls back to the web UI after the fact and `git status`/`git diff` during. Prospects would hit the same three-command conceptual load (`init --hooks`, `watch --files`, `files`). Industry status quo: invisible auto-start daemons (Docker/Gradle pattern); nearest neighbor agenttrace is post-run only — no live capture, no provenance.

Rebase note (v0.6.0): `meter run -- <cmd>` is now the proxy-side one-command front door — it launches an agent with capture auto-wired (multi-upstream, provider-labeled). The two commands split the story cleanly and share the one-command principle: **`meter run` = launch and capture** (proxy plane, API traffic); **`meter live` = watch and capture** (transcript ingest + file side effects, sessions Meterbility observes from the outside). Neither replaces the other; `run`-launched sessions show up in `live`'s stream like any other run.

## Target User & Narrowest Wedge

Same buyer as the sell-track: agent team leads (Agentforce-EM archetype) auditing what agents did to their file trees — and the founder as user zero. Wedge: a single verb (`meter live`) that makes "watch this session and its file changes" one decision instead of three, plus the missing range query. Explicitly NOT in the wedge: new capture semantics, daemons, web UI changes.

## Constraints

- Capture planes are frozen except additive, read-only instrumentation (timestamps/counters on FileSentinel for the health line — no semantics changes): the hook/sentinel planes are unchanged since v0.5.1 (v0.6.0 shipped proxy multi-upstream without touching them) and the sell-track demo window is open. Otherwise composition only — LiveInspector, FileSentinel, files.ts renderers, hook_capture attribution.
- No silent always-on capture. Audit positioning: capture is credibility, not plumbing. Consent boundary is `meter init --hooks` (explicit, once); run-time may be automatic/nudged after that.
- Degraded capture must be visible, never silent (fseventsd starvation exists in the wild; founder's own Mac is the fixture).
- Ships in the existing @meterbility/cli npm package and release pipeline.

## Premises (agreed; #4 revised after cross-model challenge)

1. The primary problem is packaging/flow, not capture capability — one command starting ingest + capture together with self-explaining status.
2. The one missing query shape is the range summary: all files changed from step X to [Y | current], no path required. Per-step view exists and needs surfacing, not rebuilding.
3. Consent at init-time, automation at run-time: the hook plane may auto-ensure/nudge the live side. No silent always-on daemon. (Session eureka: the invisible-daemon consensus puts the consent boundary in the wrong place for an audit product.)
4. **(Revised per Codex challenge)** The "only additions" symptom gets a separate investigation (filed: likely host fseventsd coalescing), AND the front door ships a capture-health indicator so degraded capture is visible, never silent.
5. Build from shipped parts only; no new capture plane; v0.5.1 capture semantics frozen.
6. Distribution is solved: existing npm package + CI.

## Approaches Considered

### Approach A: Sharpen What Exists (minimal viable)
`meter watch` gets `--files` on by default + rewritten help/status text; `meter files` gains the range summary. Effort S, risk low. Rejected as the wedge: leaves "watch" as a verb you must remember — the named pain survives the fix. (Its range-summary piece is absorbed into B.)

### Approach B: `meter live` Front Door (ideal architecture) — CHOSEN
New command composing shipped parts. Spec below.

### Approach C: Hook-Ensured Always-Capture (creative/lateral)
Hook plane auto-spawns detached ingest+sentinel on first tool call; `meter live` becomes a pure viewer; forgetting becomes impossible. Effort L, risk high (daemon lifecycle, orphan processes, hook hot-path timeout budget). Deferred, not rejected: both models flagged skip-for-now during the demo window. B's nudge mechanism is designed so C can replace it without changing the viewer surface.

## Recommended Approach

**Approach B — `meter live`.** Both models converged on this shape independently. Composition of shipped parts; capture semantics untouched.

### Command spec

`meter live [run-id-or-prefix] [--provider auto|claude|codex|cursor] [--files-dir <path>] [--json] [--no-files]`

1. **Startup header (self-explaining status):** detected active session(s) (or "none yet — start your agent; I'll attach"), capture mode per runtime (hooks=exact / sentinel=fallback / both / proxy), watched file root + ignore sources, DB path, current step of each attached run. Proxy-captured runs (v0.6 schema v6) display their first-class identity: `provider` and `upstream_host` in the header entry, and a `[provider]` tag on their stream lines — the front door must speak v0.6's provider vocabulary, not collapse everything to "proxy". Loud, colored warning when no session is active — with the one next action to take. The header prints immediately; on a cold store the initial backfill runs in the background with a progress line ("backfilling N sessions…") so attach latency is independent of history size. Progress source: the CLI approximates via the session-discovery count + spinner in v1; a small additive progress event on LiveInspector is permitted if needed (ingest side, not the frozen capture plane). SYNCING state (outside-voice T3): while the initial backfill runs, the header shows `SYNCING · backfilling N sessions`, historical events stream with a dim `[sync]` prefix, and the health line is suppressed ("waiting for sync") — no confident-but-wrong step counts or health verdicts on partial data; a `SYNCED` transition line marks catch-up.
2. **One process, both planes:** LiveInspector (incremental ingest) + FileSentinel (side-effect capture) started together, exactly as `watch --files` does today; `meter live` supersedes that flag pair as the blessed path. Concurrency policy (revised per outside-voice T2): one sentinel per root at a time, enforced without locks — on start, if `live.heartbeat` is fresh (<2 min), the new instance prints "capture already active — attaching as viewer" and runs viewer-only (no FileSentinel); `--force-capture` overrides. A crashed instance's heartbeat self-expires within 2 minutes. This eliminates the duplicate-row insert race by construction (audit logs must not carry duplicates); blob-ref dedup remains as defense in depth.
3. **Live stream:** per-step line `step 42 · Edit packages/cli/src/foo.ts · +12 −3` interleaved with run lifecycle events. `files:changed` events carry paths only, so the CLI fetches the step's FileChange rows on each event for the ± stats (cheap, indexed lookup). Re-emit handling (eng review 3A): LiveInspector re-announces a step when its row count grows (late hook-band drains); the CLI tracks announced row counts per step and prints only the NEW rows on re-emit, tagged `step 42 (update) · …` — late Bash evidence visibly arrives, no duplicate full-step lines. Renderers are extracted to a shared module (eng review 2A: `packages/cli/src/render_events.ts` exporting watch.ts's printPretty/printFileEvent) imported by both `watch` and `live` — no duplication, no command-importing-command. File rows cross-reference their step so the stream teaches the per-step query (`meter files <run> --at 42` printed as a hint on first file event). A `[run-id-or-prefix]` argument filters the *display* only — sentinel capture and ingest remain global (attribution is temporal-proximity across all in-progress runs; a filtered viewer must not silently discard captures for other runs).
4. **Capture-health line (premise 4):** periodic status line + degraded warning. Degraded is a cross-check, not a bare timer: file-touching steps were ingested within the window — counting only runs whose cwd overlaps the watched root (same `cwdOverlaps` predicate the sentinel uses for attribution, so a session editing a different repo can't fire a false warning) — AND no sentinel event arrived within the threshold (an idle repo is healthy, not degraded). "File-touching step" is sourced from data that exists even when the sentinel is dead (eng review 1A): the step's `action_json` names a file-mutating or shell tool (Edit/Write/apply_patch/Bash/shell) OR the step carries `derived_from='tool_call'` file changes; `filesystem_watch` rows never count toward the numerator — the check must not depend on output from the plane being checked. Numerator mechanics (eng review 7A): computed from the in-process ingest stream — `meter live` tags each freshly-ingested step against the 1A predicate as events arrive and keeps a 15s in-memory window; zero standing DB queries, O(1) at rest (matches the frozen-poll-cost posture in TODOS.md). Requires additive read-only instrumentation on FileSentinel: last-raw-FS-event timestamp and event counters, surfaced pre-debounce. On a starved host it must say so: "steps are editing files but no filesystem events for ≥15s — file capture degraded (host fseventsd) — hook-based capture unaffected."
5. **Range summary (the missing query):** `meter files <run-id> --from X [--to Y]` now valid WITHOUT `--diff` — renders the existing git-status-style collapsed summary (collapseByPath) restricted to the step window. `--to` omitted = latest ingested main-band step, which against an in-progress run means "to the current step" and re-runs cleanly as the run advances. Window semantics (revised per outside-voice T1): `--from`/`--to` resolve against main-band sequences, and synthetic-band rows (hooks 100k / admin 200k / checkpoints 300k) are INCLUDED by default via wall-clock mapping — a band row counts when its parent step's timestamp falls within the boundary steps' timestamps (inclusive both ends), rendered with a `(hook)`/`(admin)` tag. "Everything changed from X to now" means everything; `--main-band-only` opts out, and the footer reports what the opt-out excluded. `--at` is mutually exclusive with `--from`/`--to` (error). `--json` supported. Reuses resolveStepSeqLoose/filterByStepSeq from files.ts.
6. **Hook nudge (premise 3, C-compatible seam):** `meter live` writes a heartbeat row (settings table, `live.heartbeat` = ISO timestamp) every poll tick. Any human-invoked `meter` command (exclusions: `capture`, `cursor-hook`, `run`, and `--json` invocations — hook hot paths, scripts, and `run`'s child-stdio purity; `run` instead prints its own one-line attach hint after its proxy starts, suppressed by `--quiet`, which doubles as `meter live` discovery at the exact moment capture begins) checks: watch/hook-derived FileChange rows inserted in the last 10 minutes AND heartbeat absent or staler than 2 minutes → print one line: "capture active on <run> — `meter live` to attach." Query is `LIMIT 1` (existence check); no covering index for `derived_from`+`created_at` today — add one only if it ever shows in CLI startup latency. No background process is spawned. Safety contract (eng review 4A): the check runs only when the store file already exists (`existsSync` — never create the store as a side effect), the entire check is wrapped in a swallow-all try/catch (a decoration must never fail the command the user ran), and it skips itself past a ~50ms budget.
7. **`meter live --json`:** NDJSON, a superset of `watch --json` — same event objects, plus health as a typed event (`{"type":"capture:health","fs_event_age_ms":…,"ingest_lag_ms":…,"degraded":bool}`).
8. **`meter watch` disposition:** kept as the raw event-stream tool (JSON/scripting); its help text points humans at `meter live`. No breaking change in this ship.

## Test Plan (eng review 6A — full coverage, written alongside implementation, not after)

Framework: repo-standard `node:test` via `npm test` (scripts/run-tests.ts). Two REGRESSION GUARDS are mandatory (iron rule): (R1) `watch --files` output byte-identical after the 2A renderer extraction — existing watch/sentinel e2e tests re-run green; (R2) all 16 existing file_sentinel.test.ts tests pass unchanged after instrumentation.

**packages/cli/src/commands/live.test.ts (new)** — startup header with active session detected; no-session loud warning + next action; cold-store backfill progress line; invalid `--files-dir` continues without file capture; step line with ± stats from row fetch; re-emit prints delta rows tagged `(update)` only (3A — assert no duplicate full-step lines, late hook-band rows appear); run-filter argument filters display while other runs' captures still insert; health evaluator matrix with fake clock: healthy (raw event <5s), warn (>5s), degraded (>15s with 1A numerator satisfied), idle repo stays healthy (numerator zero), startup-grace suppression until first raw event, `no-recent-step` unattributed events counted as loss; `--json` NDJSON superset incl. typed `capture:health` event; SIGINT stops sentinel+inspector and final heartbeat write ceases.

**packages/cli/src/files.test.ts (additions)** — `--from X` only → window ends at latest main-band step; `--from X --to Y` collapsed summary matches per-step union; synthetic-band rows excluded with footer count line; `--at` + `--from`/`--to` → error; `--from > --to` → exit 2; loose resolution past end-of-run → empty window not error; `--json` shape for range mode; window containing partial/binary rows renders flags.

**packages/cli/src/nudge.test.ts (new)** — fires when hook/watch-derived rows exist in last 10 min AND heartbeat stale >2 min; silent when heartbeat fresh; silent for `capture`, `cursor-hook`, `--json` invocations; no store file → silent and does NOT create the store (4A); injected store error → command output unaffected (4A swallow).

**packages/server/src/file_sentinel.test.ts (additions)** — `lastRawEventAt`/counter update PRE-ignore (event on an ignored path advances them); `coalesced_events: n` recorded in normalizer_notes when >1 raw event per path precedes a flush; graduated investigation scenarios pinned as design-property tests: S2 (burst in one debounce window → single all-additions create), S3 (late delivery → create + unchanged-skips), S4b (same-window add-then-remove nets to +N −0); unattributed no-recent-step counter exposed and incremented.

**Rebase additions (v0.6.0)** — live header and stream lines render `provider`/`upstream_host` for a proxy-captured run (schema-v6 fixture) and omit the tag for transcript-adapter runs; `meter run` prints the attach hint after proxy start and suppresses it under `--quiet` (extend run.test.ts — 235-line suite already exists on main); nudge stays silent when the invoked command is `run`.

**E2E (one)** — start `meter live` before any session; start a scripted fake session (existing test scaffolding); assert warning → attach transition and first captured file line, using the PR #28 readiness-probe pattern with starved-host skip.

## Ship Review Hardening (2026-08-24, /ship pre-landing review + red team)

Four specialists + a red-team pass over the implementation produced two fix rounds, all landed with tests:

1. **rawPerPath leak killed** (triple-confirmed): per-path coalescing accounting moved post-ignore; global liveness counters stay pre-ignore.
2. **Guard protocol hardened**: capture claim written IMMEDIATELY at startup (TOCTOU window shrunk from minutes to ms); `meter watch --files` now participates in the same `live.heartbeat` protocol (skips a duplicate sentinel, holds the claim while capturing); future-dated heartbeats treated as stale via a shared `isLiveHeartbeatFresh` predicate (clock-skew wedge); viewer-only instances detect an orphaned state (holder gone) and warn loudly / report `viewer-orphaned` in JSON health instead of sitting sentinel-less in silence.
3. **Sentinel starts before the ingest backfill** — a cold-store sync no longer leaves a minutes-wide uncaptured window while the header claims capture.
4. **Degraded requires definite write evidence**: WRITE_TOOLS escalate to degraded; SHELL_TOOLS cap at warn (a sustained read-only Bash loop is not capture loss). §4's numerator set is now two-tiered.
5. **Terminal-injection surface closed**: sanitizer strips full C0 (incl. TAB/LF) + DEL + full C1; applied to alert messages, header title/provider/upstream_host, and all path/title/message render sites.
6. **Range/query correctness**: band wall-clock mapping compares epoch millis (mixed-precision ISO strings broke lexicographic order); step-id bounds error when the step belongs to a different run; the nudge helper orders by `created_at DESC` so it names the latest capture.
7. Maintainability: shared sources of truth for heartbeat freshness (collector), cwd-overlap predicate + SentinelHealth (server), band floors (shared), op-badge/line-stat/sanitize (render_events); nudge SQL owned by a collector helper with an injectable time budget; header uses a MAX-sequence query; per-run stream state evicted on run:completed.

Accepted residuals (documented, not fixed): announced-map re-insert on post-completion late events (bounded, conf 4); countSessionFiles one-time sync walk; test-fixture triplication in test files.
